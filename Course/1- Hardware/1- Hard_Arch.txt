================================================================================
COURS ARCHITECTURE HARDWARE : DU PC A L'EMBARQUE
================================================================================

Ce cours couvre l'architecture matérielle sous toutes ses formes, depuis
l'ordinateur de bureau x86 jusqu'aux microcontrôleurs, en passant par les
appareils IoT, les véhicules, les GPU et les accélérateurs AI. Il met en évidence
comment chaque matériel implémente les concepts de système d'exploitation
(interruptions, scheduling, mémoire, protection).

================================================================================
PARTIE 1 : FONDAMENTAUX DE L'ARCHITECTURE
================================================================================

1.1 Qu'est-ce que l'architecture hardware ?
--------------------------------------------
L'architecture hardware est l'organisation des composants physiques d'un système
informatique et des relations entre eux. Elle définit :
- Le processeur (CPU) et son jeu d'instructions (ISA)
- La mémoire (RAM, ROM, cache)
- Les interfaces d'entrée/sortie (I/O)
- Les buses de communication
- Les mécanismes de synchronisation et d'interruption

1.2 Modèle de von Neumann
--------------------------
La plupart des systèmes informatiques suivent le modèle de von Neumann :
- Un seul espace d'adressage pour données et instructions
- Un bus unique pour accéder à la mémoire
- Un processeur avec ALU, contrôleur et registres

----------------------
Utilisé dans les microcontrôleurs et DSP :
- Deux espaces d'adressage séparés (programme et données)
- Deux buses parallèles pour une exécution plus rapide

1.4 Concepts communs à tous les hardware
-----------------------------------------
- Registres CPU : espace de stockage rapide (EAX, EBX, R0, R1, etc.)
- Interruptions : signal pour interrompre le flux d'exécution
- Timer : pour la planification et les mesures de temps
- Mémoire volatile (RAM) vs non volatile (ROM, Flash)
- Ports d'E/S : communication avec les périphériques
- Bus : chemin de communication entre composants

PARTIE 2 : ARCHITECTURE X86 (PC TRADITIONNEL)
================================================================================

2.1 Historique et évolutions
-----------------------------
- 8086 (1978) : 16-bit, 1 MiB d'adressage
- 80286 (1982) : Mode protégé, 16-bit
- 80386 (1985) : 32-bit, paging, mode utilisateur/noyau
- Pentium (1993) : Superscalar, MMX
- x86-64 (2003) : 64-bit, mode long, 16 registres généraux

2.2 Modes d'exécution
----------------------
AXIOME 6 (OS.txt) : SEPARATION DES NIVEAUX DE PRIVILEGE
"Utilisation de modes d'exécution (kernel mode / user mode) pour protéger le noyau."

- Real Mode (16-bit) : Boot, 1 MiB, pas de protection
- Protected Mode (32-bit) : Mode principal, segmentation, paging
- Virtual 8086 Mode : Pour exécuter des programmes 16-bit
- Long Mode (64-bit) : x86-64, adressage étendu, registres supplémentaires

2.3 Registres x86
------------------
Registres généraux (32-bit) :
- EAX : Accumulateur (calculs, retour de fonctions)
- EBX : Base (pointeur de données)
- ECX : Compteur (boucles)
- EDX : Données (entrée/sortie)
- ESI : Index source (copie de données)
- EDI : Index destination (copie de données)
- EBP : Pointeur de base (pile)
- ESP : Pointeur de pile

Registres de segment :
- CS : Code Segment
- DS : Data Segment
- SS : Stack Segment
- ES, FS, GS : Segments supplémentaires

Registres de contrôle :
- CR0 : Bit PE (Protected Mode Enable), PG (Paging)
- CR2 : Adresse de la page fautive
- CR3 : Adresse de la Page Directory
- CR4 : Extensions (PAE, etc.)

2.4 Mémoire x86
----------------
- Adressage physique : 4 GiB (32-bit) à 256 TiB (64-bit)
- Paging : traduction adresse virtuelle → physique
- TLB : Cache pour les traductions de pages

Exemple de mapping VGA (0xB8000) :
volatile uint16_t *vga_buffer = (volatile uint16_t *)0xB8000;

2.5 Contrôleurs d'interruptions
--------------------------------
- PIC (Programmable Interrupt Controller) : 8259A, 2 PICs en cascade (IRQ 0-15)
- APIC (Advanced Programmable Interrupt Controller) : Multiprocesseur

IRQ assignments :
- IRQ 0 : PIT (Timer)
- IRQ 1 : Clavier PS/2
- IRQ 14 : Disque dur ATA
- IRQ 15 : Disque dur ATA secondaire

2.6 Boot process x86
---------------------
1. POST (Power-On Self Test) : Vérification matérielle
2. Chargement du bootloader depuis MBR (512 octets)
3. Bootloader charge le noyau en mémoire
4. Passage en Protected Mode (lgdt, CR0.PE=1)
5. Initialisation du noyau (GDT, IDT, paging)
6. Lancement du processus init

2.7 Programmation du matériel x86
----------------------------------
Accès aux ports :
static inline uint8_t inb(uint16_t port) {
    uint8_t ret;
    asm volatile ("inb %1, %0" : "=a"(ret) : "Nd"(port));
    return ret;
}

static inline void outb(uint16_t port, uint8_t val) {
    asm volatile ("outb %0, %1" : : "a"(val), "Nd"(port));
}

Accès aux registres de contrôle :
static inline uint32_t read_cr0(void) {
    uint32_t val;
    asm volatile ("mov %%cr0, %0" : "=r"(val));
    return val;
}

void pit_init(uint32_t freq) {
    uint16_t divisor = 1193182 / freq;
    outb(0x43, 0x36);
    outb(0x40, divisor & 0xFF);
    outb(0x40, divisor >> 8);
}

2.8.6 PCI/PCIe
--------------
Bus pour les périphériques.
void pci_scan_bus(void) {
    for (int bus = 0; bus < 256; bus++) {
        for (int slot = 0; slot < 32; slot++) {
            uint32_t addr = (bus << 16) | (slot << 11) | 0x80000000;
            uint32_t vendor = inl(addr);
            if (vendor != 0xFFFFFFFF) {
                // Trouvé un périphérique PCI
            }
        }
    }
}

PARTIE 3 : MICROCONTROLEURS
================================================================================

3.1 Qu'est-ce qu'un microcontrôleur ?
--------------------------------------
Un microcontrôleur (MCU) est un système sur puce (SoC) qui intègre :
- CPU (généralement RISC : ARM Cortex-M, AVR, PIC, RISC-V)
- Mémoire (RAM, Flash, EEPROM)
- Périphériques intégrés (UART, I2C, SPI, ADC, PWM, GPIO)
- Contrôleurs de puissance

3.2 Architecture ARM Cortex-M
------------------------------
ARM est l'architecture la plus utilisée dans les microcontrôleurs.

Modes d'exécution :
- Thread Mode : Mode utilisateur
- Handler Mode : Mode gestionnaire d'exceptions

Niveaux de privilège :
- Privileged : Accès complet
- Unprivileged : Accès restreint

Interruptions :
- NVIC (Nested Vectored Interrupt Controller)
- Priorités configurables
- Nesting des interruptions

Exemple : Initialisation d'une interruption sur Cortex-M
void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        char c = USART1->DR;
        // Traiter le caractère reçu
    }
}

3.3 Architecture AVR (Atmel)
-----------------------------
Utilisée dans les Arduino.

Caractéristiques :
- 8-bit ou 32-bit
- Harvard architecture
- Mémoire Flash pour le programme
- Mémoire SRAM pour les données
- Registres généraux (32 pour ATmega)

Exemple : Blink sur AVR
#define PORTB (*((volatile uint8_t *)0x25))
#define DDRB  (*((volatile uint8_t *)0x24))

int main(void) {
    DDRB |= (1 << 5); // PB5 en sortie
    while (1) {
        PORTB ^= (1 << 5); // Toggle PB5
        _delay_ms(500);
    }
}

3.4 Architecture RISC-V
------------------------
Architecture ouverte (BSD license), très utilisée aujourd'hui.

Caractéristiques :
- Modulaire : ISA de base + extensions (M, A, F, D, C)
- 32-bit ou 64-bit
- Harvard ou von Neumann
- Support pour les microcontrôleurs (RV32IMC) et les processeurs de haute performance (RV64GC)

Exemple : Initialisation UART sur RISC-V
void uart_init(void) {
    volatile uint32_t *uart_regs = (uint32_t *)0x10013000;
    uart_regs[1] = 0x1; // Enable TX
    uart_regs[0] = 0x1; // Enable RX
}

3.5 Firmware et RTOS
---------------------
Programmes exécutés sur les microcontrôleurs :

Firmware :
- Programme minimaliste, souvent écrit en assembler ou C
- Pas de système d'exploitation
- Exécution séquentielle ou basée sur interruptions

RTOS (Real-Time Operating System) :
- Système temps réel
- Gestion de tâches (scheduling prédéfini)
- Gestion de mémoire
- Synchronisation (semaphores, mutex)

Exemples de RTOS :
- FreeRTOS
- Zephyr
- RT-Thread
- μC/OS

3.6 Applications
-----------------
- Contrôleurs industriels
- IoT (capteurs, actionneurs)
- Appliances ménagères (lave-linge, réfrigérateur)
- Véhicules (ECU)
- Appareils médicaux

PARTIE 4 : DSP (Digital Signal Processor)
================================================================================

4.1 Qu'est-ce qu'un DSP ?
---------------------------
Un DSP est un processeur spécialisé dans le traitement du signal numérique :
- FFT (Transformée de Fourier)
- Filtrages numériques
- Modulation/demodulation
- Compression audio/vidéo

4.2 Architectures DSP
----------------------
- Texas Instruments TMS320C6000
- Analog Devices ADSP-BF5xx
- ARM Cortex-A avec NEON

Caractéristiques :
- Multiply-Accumulate (MAC) : Instructions dédiées
- Pipeline profond
- Architecture Harvard
- Mémoire séparée pour données et instructions

4.3 Programme DSP
------------------
Généralement des algorithmes de traitement du signal :

Exemple : Filtre numérique
void fir_filter(int16_t *input, int16_t *output, int16_t *coeffs,
                int32_t n_samples, int32_t n_taps) {
    int32_t i, j;
    int32_t sum;
    
    for (i = n_taps - 1; i < n_samples; i++) {
        sum = 0;
        for (j = 0; j < n_taps; j++) {
            sum += (int32_t)input[i - j] * (int32_t)coeffs[j];
        }
        output[i - n_taps + 1] = (int16_t)(sum >> 15);
    }
}

-----------------------

--------------------

Exemples :
- MicroBlaze (Xilinx)
- Nios II (Intel)

Exemples :
- Raspberry Pi (ARM Cortex-A53)

PARTIE 11 : GPU (GRAPHICS PROCESSING UNIT)
================================================================================

11.1 Architecture GPU
----------------------
Une GPU est un processeur parallèle composé de plusieurs blocs :

NVIDIA :
- GPC (Graphics Processing Cluster) : Groupes de SM
- SM (Streaming Multiprocessor) : Unité de calcul principale
  - CUDA cores : Calculs généralistes
  - Tensor cores : Calculs matriciels (AI)
  - RT cores : Ray tracing
- Memory Controller : Gestion de la VRAM
- NVLink : Interface haute vitesse entre GPU

AMD :
- Compute Unit : Équivalent des SM
- Stream Processors : Coeurs de calcul
- Ray Accelerators : Ray tracing
- Infinity Fabric : Communication entre GPU

Intel :
- Xe Core : Unités de calcul
- EU (Execution Unit) : Coeurs SIMD
- Thread Execution Manager

11.2 Hierarchie de la mémoire GPU
----------------------------------
- Registers : Mémoire la plus rapide (par thread)
- Shared Memory : Mémoire partagée entre threads d'un bloc
- L1 Cache : Cache par SM
- L2 Cache : Cache partagé entre tous les SM
- VRAM : Mémoire principale (GDDR6, HBM)

11.3 Interface avec le CPU
---------------------------
- PCIe : Interface standard (x16, 16 GT/s)
- NVLink : NVIDIA, plus rapide que PCIe
- CXL : Compute Express Link (standard open)

11.4 Concepts OS dans les GPU
------------------------------
- Kernels : Programmes exécutés en parallèle
- Thread blocks : Groupes de threads
- Warp/Wavefront : Unités d'exécution SIMD
- Synchronisation (barriers)
- Memory coalescing : Optimisation de l'accès mémoire

----------------------------
- Basse consommation énergétique
- Communication sans fil
- Sécurité (TLS, DTLS)
- Mise à jour OTA

13.5 Exemple : Capteur de température
--------------------------------------
void sensor_read(float *temperature) {
    int raw = adc_read(0);
    *temperature = (raw * 3.3 / 4096) * 100;
}

void mqtt_publish(const char *topic, float value) {
    char payload[32];
    sprintf(payload, "%.2f", value);
    mqtt_send(topic, payload, strlen(payload));
}

PARTIE 15 : CONCEPTS OS APPLIQUES AUX DIFFERENTS HARDWARE
================================================================================

15.1 Interruptions
-------------------
- x86 : PIC/APIC, IDT, ISR
- ARM Cortex-M : NVIC, vectored interrupts
- ARM Cortex-A : GIC (Generic Interrupt Controller), VBAR
- RISC-V : PLIC/CLIC, stvec
- AVR : Interrupt vectors table
- DSP : DMA interrupts

15.2 Scheduling
----------------
- x86 : Round Robin, CFS (Linux)
- RTOS : Priority-based, Rate Monotonic
- DSP : Static scheduling (algorithmes prédéfinis)
- GPU : Warp scheduling

15.3 Mémoire
-------------
- x86 : Paging, mémoire virtuelle
- ARM : MMU, TTBR0/TTBR1, MAIR
- RISC-V : satp, Sv39/Sv48
- Microcontrôleurs : Mémoire physique, stack limitée
- GPU : VRAM, shared memory
- IoT : Flash pour le programme, RAM limitée

15.4 Protection
----------------
- x86 : Rings (0-3), MMU
- ARM : EL0/EL1/EL2/EL3, MPU/MMU
- RISC-V : U/S/M modes, PMP
- RTOS : Task isolation
- IoT : Sandboxing minimal

15.5 Communication
-------------------
- x86 : PCIe, USB, SATA
- Microcontrôleurs : I2C, SPI, UART
- Automotive : CAN, LIN
- IoT : MQTT, CoAP

16.2 Modes d'exécution
-----------------------
x86 :
- Ring 0 : Kernel mode
- Ring 1 : Device drivers
- Ring 2 : Reserved
- Ring 3 : User mode

ARM :
- EL0 : User mode
- EL1 : Kernel mode
- EL2 : Hypervisor mode
- EL3 : Secure monitor (TrustZone)

RISC-V :
- U mode : User mode
- S mode : Supervisor mode (kernel)
- M mode : Machine mode (firmware)

16.3 Tables de traduction
--------------------------
x86 :
- Page Directory (CR3)
- Page Table
- Niveaux : 2 (32-bit), 4 (64-bit avec PAE)

ARM :
- Translation Table Base Register (TTBR0/TTBR1)
- Niveaux : 2 ou 3
- MAIR (Memory Attribute Indirection Register)

RISC-V :
- satp (Supervisor Address Translation and Protection)
- Sv39 : 39-bit, 3 niveaux
- Sv48 : 48-bit, 4 niveaux

16.4 Interruptions
-------------------
x86 :
- IDT (Interrupt Descriptor Table)
- PIC/APIC
- IRET pour retour

ARM :
- VBAR (Vector Base Address Register)
- GIC (Generic Interrupt Controller)
- ERET pour retour

RISC-V :
- stvec (Supervisor Trap Vector)
- PLIC (Platform Level Interrupt Controller)
- sret/mret pour retour

16.5 Boot Process
------------------
x86 :
1. POST
2. MBR/UEFI
3. Bootloader (GRUB)
4. Kernel

ARM :
1. ROM code
2. Bootloader (U-Boot)
3. Kernel
4. Device Tree

RISC-V :
1. ROM/Firmware
2. OpenSBI (Supervisor Binary Interface)
3. Bootloader (U-Boot)
4. Kernel

PARTIE 17 : SECURITE HARDWARE
================================================================================

17.1 TPM (Trusted Platform Module)
-----------------------------------
Module de sécurité matérielle pour :
- Stockage sécurisé de clés
- Mesure d'intégrité (PCR)
- Cryptographie (RSA, AES)
- Secure Boot

17.2 ARM TrustZone
-------------------
Extension de sécurité qui divise le système en :
- Secure World : Code sécurisé (firmware, DRM)
- Normal World : OS et applications

Modes :
- EL3 : Secure Monitor (passage entre mondes)
- Secure EL1 : Code sécurisé
- Normal EL1 : Kernel
- Normal EL0 : Applications

17.3 RISC-V PMP (Physical Memory Protection)
---------------------------------------------
Protection de la mémoire physique par zones configurables.
Chaque zone peut avoir les permissions :
- Read (R)
- Write (W)
- Execute (X)

17.4 Secure Boot
-----------------
Vérification de l'intégrité du firmware et du kernel avant l'exécution.

Chain of Trust :
1. ROM (Immutable)
2. Secure Bootloader
3. Kernel
4. Applications

17.5 Anti-tampering
--------------------
Mécanismes pour détecter les modifications :
- CRC de code
- Détection de débugging
- Protection contre la lecture de mémoire

17.6 Cryptographie matérielle
------------------------------
- AES accelerator
- SHA engine
- RSA/ECC coprocessor
