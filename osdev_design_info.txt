PARTIE 1 : PRINCIPES DE CONCEPTION FONDAMENTAUX
================================================================================

1.1 Principes Généraux
-----------------------
Les principes clés pour concevoir un OS :

1. **Modularité** : Décomposer le système en composants indépendants
   - Avantages : maintenance simplifiée, testabilité, réutilisabilité
   - Principe : chaque module a une fonction spécifique et une interface bien définie

2. **Abstraction** : Cacher les détails d'implémentation derrière des interfaces
   - Exemples : système de fichiers, pilotes de périphériques, mémoire virtuelle

3. **Stratification (Layering)** : Organiser le système en niveaux hiérarchiques
   - Chaque couche utilise les services de la couche inférieure
   - Couches typiques : Hardware → Kernel → Pilotes → FS → API → Applications

4. **Efficacité** : Optimiser l'utilisation des ressources
   - Utilisation CPU, mémoire, I/O

5. **Fiabilité** : Assurer la stabilité et la tolérance aux fautes
   - Gestion des erreurs, redondance, récupération

6. **Extensibilité** : Permettre au système de croître
   - Ajout de fonctionnalités sans casser les existantes

7. **Sécurité** : Protéger les ressources contre accès non autorisé
   - Authentification, contrôle d'accès, chiffrement

1.2 Critères d'Évaluation
--------------------------
| Critère | Description |
|---------|-------------|
| Performance | Temps de réponse, débit, utilisation CPU/mémoire |
| Fiabilité | Temps entre pannes, récupération automatique |
| Sécurité | Protection contre attaques, isolation des processus |
| Extensibilité | Facilité d'ajout de fonctionnalités |
| Portabilité | Capacité à fonctionner sur différentes architectures |
| Maintainabilité | Facilité de modification et de débogage |

PARTIE 2 : ARCHITECTURES DE NOYAU
================================================================================

2.1 Architecture Monolithique
------------------------------
Toutes les fonctions du noyau sont implémentées dans un espace unique.

**Avantages** :
- Performance supérieure (pas de saut mode utilisateur/noiyau)
- Implémentation plus simple
- Communication rapide entre modules

**Inconvénients** :
- Codebase volumineux
- Moins modulaire
- Un bug peut affecter l'ensemble du système
- Maintenance difficile

**Exemples** : Linux (partiellement), DOS, BSD

2.2 Architecture en Couches (Layered)
--------------------------------------
Organisation hiérarchique où chaque couche fournit des services à la couche supérieure.

**Principe** :
- Couche 0 : Matériel
- Couche 1 : Gestion bas niveau (interruptions, I/O)
- Couche 2 : Gestion mémoire
- Couche 3 : Gestion processus
- Couche 4 : Système de fichiers
- Couche 5 : Interface utilisateur

**Avantages** :
- Simplicité de conception
- Testabilité (chaque couche peut être testée indépendamment)
- Maintenance facilitée

**Inconvénients** :
- Perte de performance (appels entre couches)
- Rigidité (modification d'une couche peut affecter les autres)

**Exemples** : THE OS (Dijkstra), MULTICS

2.3 Architecture Microkernel
-----------------------------
Seules les fonctions essentielles sont dans le noyau.

**Fonctions essentielles** :
- Planification des processus
- Gestion mémoire bas niveau
- Communication inter-processus (IPC)
- Gestion des interruptions

**Services exécutés en espace utilisateur** :
- Système de fichiers
- Pilotes de périphériques
- Services réseau
- Gestion de la sécurité

**Avantages** :
- Modularité maximale
- Sécurité améliorée (isolement des services)
- Fiabilité (un service planté n'affecte pas le noyau)
- Facile à étendre

**Inconvénients** :
- Performance réduite (IPC entre espace utilisateur/noiyau)
- Complexité accrue

**Exemples** : MINIX, Mach, QNX

2.4 Architecture Hybride
-------------------------
Combinaison des architectures monolithique et microkernel.

**Principe** :
- Services critiques dans le noyau pour la performance
- Services moins critiques en espace utilisateur

**Exemples** : Windows NT/2000/XP/Vista/7/8/10, Linux (avec modules)

2.5 Architecture Exokernel
---------------------------
Le noyau ne fournit que l'allocation de ressources.

**Principe** :
- L'application gère les ressources qu'elle a obtenues
- Pas d'abstraction forcée
- Contrôle maximal pour les applications

**Avantages** :
- Performance maximale
- Flexibilité

**Inconvénients** :
- Complexité pour les développeurs
- Moins d'abstraction

**Exemples** : Exokernel (MIT), Nemesis

2.6 Architecture Modulaire
---------------------------
Extension de l'architecture monolithique avec chargement dynamique.

**Principe** :
- Modules chargés/déchargés à l'exécution
- Interface standardisée

**Avantages** :
- Performance proche du monolithique
- Modularité
- Facile à étendre

**Exemples** : Linux

PARTIE 3 : GESTION DES PROCESSUS
================================================================================

3.1 Modèle de Processus
-------------------------

**États du processus** (Modèle à 5 états) :
1. **Nouveau (New)** : Processus créé, non encore ajouté à la file d'attente
2. **Prêt (Ready)** : Processus prêt à s'exécuter, en attente du CPU
3. **En cours d'exécution (Running)** : Processus utilise le CPU
4. **Bloqué (Blocked)** : Processus en attente d'un événement (I/O, signal)
5. **Terminé (Terminated)** : Processus fini d'exécuter

**Process Control Block (PCB)** :
Structure de données contenant les informations sur un processus :
- PID (Process ID)
- État
- Registres CPU
- Allocation mémoire
- Descripteurs de fichiers
- Priorité
- Statistiques d'exécution
- Pointeur vers le processus parent

3.2 Algorithmes de Planification
---------------------------------

**Algorithmes de planification de base** :

1. **First-Come, First-Served (FCFS)**
   - Principe : Premiers arrivés, premiers servis
   - Avantages : Simple, équitable
   - Inconvénients : Effet convoyage (long processus retarde les courts)
   - Temps d'attente moyen : peut être élevé

2. **Shortest Job First (SJF)**
   - Principe : Priorité aux processus avec temps d'exécution le plus court
   - Avantages : Temps d'attente minimal théoriquement
   - Inconvénients : Connaissance du temps d'exécution nécessaire, risque de famine pour les longs processus
   - Version préemptive : Shortest Remaining Time First (SRTF)

3. **Round Robin (RR)**
   - Principe : Chaque processus reçoit un quantum de temps fixe
   - Avantages : Temps de réponse rapide, équitable
   - Inconvénients : Dépend du quantum (trop petit → overhead, trop grand → FCFS)
   - Idéal pour les systèmes temps partagé

4. **Scheduling par Priorité**
   - Principe : Processus avec priorité la plus haute s'exécute d'abord
   - Avantages : Fléxible
   - Inconvénients : Risque de famine pour les processus à basse priorité
   - Solution : Vîllesse (aging) - augmentation de la priorité avec le temps d'attente

5. **File d'attente à plusieurs niveaux (Multilevel Queue)**
   - Principe : Classes de processus (système, interactive, batch)
   - Chaque classe a son propre algorithme de planification
   - Priorité entre les classes

6. **File d'attente à plusieurs niveaux avec feedback (Multilevel Feedback Queue)**
   - Principe : Processus peuvent passer entre les classes
   - Les processus utilisant beaucoup de CPU descendent de classe
   - Les processus I/O-bound montent de classe

**Algorithmes temps réel** :

1. **Rate Monotonic Scheduling (RMS)**
   - Principe : Priorité proportionnelle à la fréquence d'exécution
   - Tâche avec période la plus courte → priorité la plus haute
   - Analyse de schedulabilité : Σ(utilisation) ≤ n(2^(1/n) - 1)

2. **Earliest Deadline First (EDF)**
   - Principe : Priorité à la tâche avec la date d'échéance la plus proche
   - Optimal pour les systèmes à priorités dynamiques
   - Analyse de schedulabilité : Σ(utilisation) ≤ 1

3. **Least Laxity First (LLF)**
   - Principe : Priorité à la tâche avec le moins de laxité
   - Laxité = Deadline - Temps restant à exécuter - Temps actuel

3.3 Synchronisation des Processus
----------------------------------

**Problèmes de concurrence** :
- Conditions de course (Race Conditions)
- Interblocage (Deadlock)
- Inversion de priorité (Priority Inversion)

**Primitives de synchronisation** :

1. **Mutex (Mutual Exclusion)**
   - Verrou exclusif
   - Un seul processus peut détenir le mutex à la fois
   - Opérations : lock(), unlock()

2. **Sémaphore**
   - Compteur qui contrôle l'accès à une ressource
   - Opérations : P() (décrémente, bloque si ≤ 0), V() (incrémente, débloque)
   - Sémaphore binaire (0 ou 1) = Mutex
   - Sémaphore de comptage (> 1) = gestion de plusieurs instances

3. **Moniteur**
   - Structure de données + procédures d'accès
   - Mutual exclusion automatique
   - Variables de condition pour la synchronisation

4. **Spinlock**
   - Boucle active jusqu'à obtention du verrou
   - Idéal pour de courts accès (évite le coût de blocage)

5. **Barrière (Barrier)**
   - Tous les processus doivent atteindre un point avant de poursuivre

**Problèmes classiques de synchronisation** :

1. **Producteur-Consommateur**
   - Buffer partagé entre producteurs et consommateurs
   - Synchronisation pour éviter les conditions de course

2. **Lecture/Écriture (Readers-Writers)**
   - Plusieurs lecteurs simultanément autorisés
   - Un seul écrivain à la fois
   - Variantes : Priorité aux lecteurs, priorité aux écrivains

3. **Dîner des philosophes**
   - 5 philosophes, 5 fourchettes
   - Chaque philosophe doit prendre deux fourchettes pour manger
   - Risque d'interblocage

3.4 Communication Inter-Processus (IPC)
----------------------------------------

**Mécanismes d'IPC** :

1. **Mémoire partagée (Shared Memory)**
   - Région de mémoire accessible à plusieurs processus
   - Performance maximale (pas de copie de données)
   - Nécessite synchronisation (mutex, sémaphore)

2. **Passage de messages (Message Passing)**
   - Échange de messages via des files de messages
   - Synchronisation intégrée
   - Moins performant (copie de données)
   - Types :
     - Synchrones (réception bloque l'expéditeur)
     - Asynchrones (expéditeur continue)
     - Avec confirmation (ACK)

3. **Pipes**
   - Tube unidirectionnel entre processus liés
   - Utilisé pour la communication parent-enfant
   - Exemple : commande | commande

4. **Files de messages (Message Queues)**
   - Messages organisés en files
   - Processus non liés peuvent communiquer
   - Messages peuvent être priorisés

5. **Tampons (Buffers)**
   - FIFO pour communication entre processus
   - Synchronisation automatisée

6. **Sockets**
   - Communication entre processus sur le même ordinateur ou sur le réseau
   - Protocole TCP/IP ou UDP

7. **Signaux (Signals)**
   - Notification asynchrone d'événements
   - Exemples : SIGINT (interruption), SIGTERM (terminaison), SIGKILL (forcage)

PARTIE 4 : GESTION DE LA MEMOIRE
================================================================================

4.1 Organisation de la Mémoire
-------------------------------

**Hiérarchie mémoire** :
1. Registres CPU (ns)
2. Cache L1/L2/L3 (ns-μs)
3. Mémoire vive (RAM) (μs)
4. Disque dur (ms)
5. Stockage secondaire (min)

**Principe de localité** :
- Localité temporelle : Une donnée accédée est susceptible d'être réaccédée
- Localité spatiale : Les données adjacentes sont susceptibles d'être accédées

4.2 Allocation de Mémoire Continue
-----------------------------------

**Stratégies d'allocation** :

1. **Premier ajustement (First Fit)**
   - Recherche de la première zone libre suffisamment grande
   - Simple, rapide
   - Peut créer des fragments internes

2. **Meilleur ajustement (Best Fit)**
   - Recherche de la plus petite zone libre suffisamment grande
   - Minimise les fragments
   - Plus lent (recherche exhaustive)

3. **Pire ajustement (Worst Fit)**
   - Allocation dans la plus grande zone libre
   - Conserve les petites zones pour les petites allocations
   - Peut créer des fragments

4. **Suivant ajustement (Next Fit)**
   - Similaire à First Fit mais démarre la recherche depuis la dernière allocation
   - Plus rapide que First Fit
   - Peut créer des fragments à la fin

**Défragmentation** :
- Compaction : Déplacer les processus pour fusionner les zones libres
- Coût élevé (temps CPU, I/O)

4.3 Allocation de Mémoire Non Continue
---------------------------------------

**Paging** :
- Mémoire divisée en pages (taille fixe : 4KiB, 8KiB, 16KiB)
- Table de pages pour mapper adresses virtuelles → physiques
- Pas de fragmentation externe
- Fragments internes possibles

**Segmentation** :
- Mémoire divisée en segments (taille variable)
- Chaque segment correspond à une partie logique (code, données, pile)
- Table de segments
- Fragments externes possibles

**Paging + Segmentation** :
- Combinaison des deux
- Utilisé par x86 en mode protégé

4.4 Mémoire Virtuelle
----------------------

**Principe** :
- Extension de la mémoire physique par utilisation du disque
- Chaque processus voit une mémoire virtuelle continue
- Pages peu utilisées sont écrites sur disque (swap)

**Avantages** :
- Plus de mémoire disponible
- Isolation entre processus
- Protection de la mémoire

**Algorithmes de remplacement de pages** :

1. **FIFO (First-In, First-Out)**
   - Remplace la page la plus ancienne
   - Simple à implémenter
   - Anomalie de Belady (plus de frames → plus de défauts de page)

2. **LRU (Least Recently Used)**
   - Remplace la page la moins récemment utilisée
   - Bonnes performances
   - Coût élevé (suivi de l'âge des pages)
   - Implémentation : tableau d'âge, pile, bit référence

3. **Optimal (OPT)**
   - Remplace la page qui ne sera pas utilisée le plus longtemps
   - Performances optimales
   - Impossible à implémenter (connaissance future)
   - Utilisé comme référence

4. **MRU (Most Recently Used)**
   - Remplace la page la plus récemment utilisée
   - Bon pour les accès séquentiels

5. **Clock**
   - Algorithme approximatif de LRU
   - Bit de référence pour chaque page
   - Balayage circulaire
   - Si bit = 0 → remplace ; si bit = 1 → réinitialise à 0

6. **Second Chance**
   - Variante de Clock
   - Page avec bit = 1 obtient une seconde chance

7. **Enhanced Clock**
   - Utilise bits de référence et de modification
   - Priorise les pages non modifiées

**Algorithmes d'allocation de cadres** :

1. **Allocation égale (Equal Allocation)**
   - Chaque processus reçoit le même nombre de cadres

2. **Allocation proportionnelle (Proportional Allocation)**
   - Nombre de cadres proportionnel à la taille du processus

3. **Allocation basée sur la demande (Demand Allocation)**
   - Cadres alloués au fur et à mesure de la demande

**Thrashing** :
- Phénomène où le système dépense plus de temps à échanger des pages qu'à exécuter du code
- Cause : manque de cadres mémoire
- Solution : augmentation de la mémoire, réduction du nombre de processus, pré-allocation

4.5 Allocation de Mémoire Dynamique
------------------------------------

**Algorithmes d'allocation** :

1. **Buddy System**
   - Mémoire divisée en blocs de taille 2^k
   - Allocation dans le plus petit bloc suffisant
   - Fusion automatique des blocs voisins

2. **Bitmap**
   - Tableau de bits où chaque bit représente un bloc
   - 1 = utilisé, 0 = libre
   - Recherche de séquences de bits à 0

3. **Liste chaînée**
   - Liste des zones libres
   - Chaque zone contient : taille, adresse, pointeur suivant
   - Allocation selon First/Best/Worst Fit

4. **Slab Allocation**
   - Utilisé par Linux
   - Cache de structures de données pré-allouées
   - Réduction du fragmentation

PARTIE 5 : SYSTEME DE FICHIERS
================================================================================

5.1 Concepts Fondamentaux
--------------------------

**Abstraction fichier** :
- Collection d'octets avec un nom
- Interface uniforme pour accéder aux données
- Masque les détails du stockage

**Propriétés d'un fichier** :
- Nom
- Taille
- Date de création/modification/accès
- Propriétaire
- Permissions d'accès
- Type (texte, binaire, exécutable)

**Structure de répertoires** :
- Arborescence hiérarchique
- Répertoire racine (/)
- Répertoire courant (.)
- Répertoire parent (..)

5.2 Organisation du Stockage
-----------------------------

**Disques durs** :
- Secteurs (512 octets, 4KiB)
- Cylindres, têtes, secteurs
- Temps d'accès : temps de rotation + temps de recherche

**Allocation de fichiers** :

1. **Allocation continue**
   - Fichier stocké dans un bloc continu
   - Lecture rapide
   - Fragmentation externe
   - Taille fixe à la création

2. **Allocation chaînée**
   - Blocs liés par des pointeurs
   - Aucune fragmentation externe
   - Lecture séquentielle efficace
   - Lecture aléatoire lente (suivi des pointeurs)
   - Risque de perte de données si pointeur corrompu

3. **Allocation par table d'allocation (FAT)**
   - Table contenant l'index du bloc suivant pour chaque bloc
   - Utilisé par DOS, Windows
   - Lecture aléatoire améliorée
   - Taille limitée par la table FAT

4. **Allocation indexée**
   - Inode contenant des pointeurs vers les blocs
   - Pointeurs directs, indirects uniques, indirects doubles
   - Utilisé par Unix (UFS), ext2/ext3/ext4
   - Lecture aléatoire rapide
   - Pas de fragmentation externe

**Inode (Index Node)** :
- Structure contenant les métadonnées d'un fichier
- Numéro d'inode unique
- Tableau de pointeurs vers les blocs de données

5.3 Stratégies de Placement sur Disque
---------------------------------------

1. **Placement séquentiel**
   - Fichiers stockés les uns après les autres
   - Simple
   - Fragmentation

2. **Placement par zone**
   - Zones dédiées à différents types de fichiers
   - Amélioration de la performance

3. **Placement optimisé**
   - Utilisation de l'algorithme SCAN ou C-SCAN

5.4 Algorithmes de Scheduling Disque
-------------------------------------

1. **FCFS (First-Come, First-Served)**
   - Traitement dans l'ordre d'arrivée
   - Simple, équitable
   - Performance médiocre (bras de disque se déplace aléatoirement)

2. **SSTF (Shortest Seek Time First)**
   - Priorité à la requête la plus proche
   - Performance meilleure que FCFS
   - Risque de famine pour les requêtes éloignées

3. **SCAN (Elevator Algorithm)**
   - Bras de disque se déplace dans un sens
   - Traite toutes les requêtes sur le chemin
   - Puis inverse le sens
   - Équitable, bonne performance

4. **C-SCAN (Circular SCAN)**
   - Bras de disque se déplace dans un seul sens
   - Après avoir atteint le bord, revient directement au début
   - Meilleure distribution du temps d'attente

5. **C-LOOK**
   - Variante de C-SCAN
   - Revient au plus proche de la première requête en attente

5.5 Cache de Disque
--------------------

**Principe** :
- Mémoire RAM utilisée pour stocker les blocs les plus fréquemment accédés
- Réduction des accès disque

**Algorithmes de remplacement** :
- LRU
- LFU (Least Frequently Used)
- FIFO

**Write-back vs Write-through** :
- Write-back : Écriture en cache, synchronisation avec disque plus tard
- Write-through : Écriture simultanée en cache et sur disque

5.6 Sécurité des Fichiers
--------------------------

**Permissions Unix** :
- Lecture (r), Écriture (w), Exécution (x)
- Propriétaire, Groupe, Autres
- Chmod pour modifier les permissions

**ACLs (Access Control Lists)** :
- Liste de contrôle d'accès étendue
- Permissions pour utilisateurs/groups spécifiques

**Chiffrement de fichiers** :
- Chiffrement au niveau du fichier ou du système de fichiers
- Protection contre accès non autorisé

PARTIE 6 : GESTION D'ENTREE/SORTIE
================================================================================

6.1 Concepts Fondamentaux
--------------------------

**Périphériques I/O** :
- Caractéristiques : vitesse, latence, mode d'accès
- Types :
  - Bloqués (disques, lecteurs CD)
  - Caractères (clavier, terminal, ports série)
  - Réseau (interfaces réseau)

**Modes de transfert** :

1. **Polling (Vérification périodique)**
   - CPU vérifie l'état du périphérique à intervalles réguliers
   - Simple
   - Gaspi de CPU

2. **Interrupts (Interruptions)**
   - Périphérique signale le CPU quand prêt
   - Plus efficace que polling
   - Coût d'interruption

3. **DMA (Direct Memory Access)**
   - Contrôleur DMA transfère les données directement entre périphérique et mémoire
   - CPU libéré pendant le transfert
   - Meilleure performance pour les transferts volumineux

4. **PIO (Programmed I/O)**
   - CPU lit/écrit directement les ports I/O
   - Utilisé pour les périphériques à faible débit

6.2 Architecture du Sous-système I/O
--------------------------------------

**Couches** :
1. **Interface utilisateur** : API (fopen, read, write)
2. **Système de fichiers** : Gestion des fichiers
3. **Gestionnaire de périphériques** : Allocation des ressources
4. **Pilotes de périphériques** : Code spécifique au matériel
5. **Contrôleurs matériels** : Interface avec le matériel

**Pilotes de périphériques** :
- Interface entre noyau et périphérique
- Responsabilités :
  - Initialisation du périphérique
  - Gestion des interruptions
  - Transfert de données
  - Gestion des erreurs

**Types de pilotes** :
- Pilotes de caractères (tty, mouse)
- Pilotes de blocs (disques)
- Pilotes réseau (ethernet, wifi)

6.3 Buffering
--------------

**Objectif** :
- Amélioration de la performance
- Isolation entre application et périphérique

**Types de buffers** :

1. **Buffer simple**
   - Un seul buffer par périphérique
   - Simples

2. **Double buffering**
   - Deux buffers : un pour lecture, un pour écriture
   - Réduction du temps d'attente

3. **Circular buffering**
   - Plusieurs buffers organisés en cercle
   - Utilisé pour les flux de données

4. **Buffer tampon (Cache)**
   - Mémoire RAM utilisée pour stocker les données fréquemment accédées

**Synchronisation du buffering** :
- Producer-consumer problem
- Utilisation de sémaphores ou de mutex

6.4 Spooling
-------------

**Principe** :
- Utilisation d'un espace de stockage intermédiaire (spool)
- Permet à plusieurs processus d'accéder à un périphérique partagé

**Exemples** :
- Imprimantes (file d'attente d'impression)
- Lecteurs de bandes magnétiques

PARTIE 7 : INTERBLOCAGE (DEADLOCK)
================================================================================

7.1 Concepts Fondamentaux
--------------------------

**Définition** :
Situation où deux ou plusieurs processus sont bloqués en attendant une ressource détenue par un autre processus bloqué.

**Conditions nécessaires pour un interblocage** (Coffman conditions) :

1. **Mutual Exclusion** : Au moins une ressource ne peut pas être partagée
2. **Hold and Wait** : Un processus détient une ressource et attend une autre
3. **No Preemption** : Les ressources ne peuvent pas être retirées forcément
4. **Circular Wait** : Chaîne circulaire de processus en attente

**Conditions suffisantes** :
- Graph de dépendance avec cycle

7.2 Détection d'Interblocage
-----------------------------

**Graph d'allocation de ressources** :
- Nœuds : processus et ressources
- Arêtes : requête (P → R) ou allocation (R → P)
- Cycle → interblocage

**Algorithme de détection** :
1. Construction du graph
2. Recherche de cycles
3. Si cycle trouvé → interblocage

7.3 Prévention d'Interblocage
-------------------------------

**Méthodes** :

1. **Violer la condition Mutual Exclusion**
   - Partager toutes les ressources (pas toujours possible)

2. **Violer la condition Hold and Wait**
   - Demander toutes les ressources à la fois
   - Ou libérer toutes les ressources avant de demander de nouvelles

3. **Violer la condition No Preemption**
   - Retirer les ressources forcément si un processus attend trop longtemps

4. **Violer la condition Circular Wait**
   - Ordre total des ressources
   - Chaque processus demande les ressources dans l'ordre spécifié

7.4 Évitement d'Interblocage
------------------------------

**Algorithme du banquier (Banker's Algorithm)** :
- Algorithme de vérification de sécurité
- Vérifie si une allocation est sûre avant de la faire
- Garantit qu'il existe une séquence sûre de terminaison

**Principe** :
1. État courant : allocation, demande, ressources disponibles
2. Vérification de sécurité : recherche d'un processus pouvant terminer
3. Si sécurité → allocation autorisée
4. Sinon → allocation refusée

**Complexité** : O(n^2 * m) où n = nombre de processus, m = nombre de types de ressources

7.5 Gestion d'Interblocage
---------------------------

**Stratégies** :

1. **Ignorer l'interblocage**
   - Supposer qu'il se produit rarement
   - Utilisé par Unix, Windows

2. **Détection et récupération**
   - Détecter l'interblocage
   - Récupérer en tuant un processus ou en retirant des ressources

3. **Prévention**
   - Appliquer une des méthodes de prévention

4. **Évitement**
   - Appliquer l'algorithme du banquier

**Récupération** :
- Termination de processus (un ou plusieurs)
- Préemption de ressources
- Rollback de processus

PARTIE 8 : SECURITE ET PROTECTION
================================================================================

8.1 Concepts Fondamentaux
--------------------------

**Protection** :
- Mécanismes pour contrôler l'accès aux ressources
- Objectif : prévenir les accès non autorisés

**Sécurité** :
- Protèger le système contre les attaques internes et externes
- Objectif : garantir l'intégrité, la confidentialité et la disponibilité

8.2 Mécanismes de Protection
-----------------------------

**Modes d'exécution** :
- Mode noyau (kernel mode) : accès complet au matériel
- Mode utilisateur (user mode) : accès restreint
- Passage mode utilisateur → noyau via appels système ou interruptions

**Anneaux de protection** :
- Hiérarchie de privilèges (Intel x86 : 4 anneaux)
- Anneau 0 : mode noyau (plus de privilèges)
- Anneau 3 : mode utilisateur (moins de privilèges)

**Tables de protection** :
- GDT (Global Descriptor Table) : descripteurs de segments
- LDT (Local Descriptor Table) : descripteurs locaux
- Permissions par segment : lecture, écriture, exécution

**Paging avec protection** :
- Bits U/S (User/Supervisor) : accès utilisateur ou noyau
- Bits R/W (Read/Write) : lecture seule ou lecture/écriture
- Bit XD (Execute Disable) : interdiction d'exécution

8.3 Contrôle d'Accès
---------------------

**Modèles de contrôle d'accès** :

1. **DAC (Discretionary Access Control)**
   - Propriétaire du fichier contrôle les permissions
   - Utilisé par Unix, Windows
   - Permissions rwx pour propriétaire, groupe, autres

2. **MAC (Mandatory Access Control)**
   - Contrôle centralisé par l'administration
   - Basé sur des niveaux de classification
   - Utilisé dans les systèmes sécurisés (militaire)

3. **RBAC (Role-Based Access Control)**
   - Accès basé sur le rôle de l'utilisateur
   - Utilisé dans les entreprises
   - Rôles : administrateur, utilisateur, invité

4. **ABAC (Attribute-Based Access Control)**
   - Accès basé sur des attributs (utilisateur, ressource, environnement)
   - Plus flexible

**Listes de contrôle d'accès (ACLs)** :
- Liste d'utilisateurs/groups avec leurs permissions
- Plus granulaire que les permissions Unix standard

8.4 Authentification
---------------------

**Méthodes** :
- Mot de passe (hashé, pas stocké en clair)
- Clés publiques/privées
- Certificats numériques
- Biométrie (empreinte, reconnaissance faciale)
- Tokens (carte à puce, application authenticatrice)

**Sécurité des mots de passe** :
- Hashage avec sel (salt)
- Algorithmes forts (bcrypt, scrypt, Argon2)
- Temps d'expiration
- Complexité minimale

8.5 Sécurité du Noyau
----------------------

**Bonnes pratiques** :
- Validation de toutes les entrées (sanitisation)
- Vérification des limites (buffer overflow)
- Isolation des processus
- Chiffrement des communications internes
- Audit des accès

**Vulnérabilités courantes** :
- Buffer overflow
- Race conditions
- SQL injection (pour les bases de données)
- Cross-site scripting (XSS)
- Privilege escalation

================================================================================
PARTIE 9 : VIRTUALISATION
================================================================================

9.1 Concepts Fondamentaux
--------------------------

**Virtualisation** :
- Abstraction du matériel pour créer des machines virtuelles (VM)
- Chaque VM fonctionne comme un ordinateur indépendant

**Types de virtualisation** :

1. **Virtualisation complète**
   - Hyperviseur directement sur le matériel
   - VM exécutent un OS complet
   - Exemples : VMware ESX, Xen, KVM

2. **Virtualisation par conteneur**
   - Partage du noyau hôte
   - Isolation à l'espace utilisateur
   - Plus léger que les VM
   - Exemples : Docker, LXC

3. **Virtualisation de bureau**
   - VM dans une fenêtre
   - Exemples : VirtualBox, VMware Workstation

9.2 Hyperviseurs
-----------------

**Type 1 (Bare-metal)** :
- Installe directement sur le matériel
- Bonne performance
- Utilisé dans les data centers

**Type 2 (Hosted)** :
- Installe sur un OS existant
- Moins performant que Type 1
- Utilisé pour le développement et les tests

9.3 Paravirtualisation
-----------------------

**Principe** :
- OS invité modifié pour coopérer avec l'hyperviseur
- Appels système remplacés par des appels hyperviseur
- Meilleure performance que la virtualisation complète

**Exemples** : Xen

9.4 Virtualisation Hardware-Assisted
-------------------------------------

**Extensions matérielles** :
- Intel VT-x
- AMD-V
- Permettent à l'hyperviseur de gérer les VM sans intervention logicielle

**Avantages** :
- Performance proche du matériel natif
- Sécurité améliorée

PARTIE 10 : SYSTEMES DISTRIBUES
================================================================================

10.1 Concepts Fondamentaux
---------------------------

**Système distribué** :
- Ensemble de machines indépendantes connectées par un réseau
- Coopèrent pour fournir un service unifié

**Caractéristiques** :
- Hétérogénéité (différentes architectures, OS)
- Tolérance aux fautes
- Concurrence
- Manque de synchronisation globale
- Latence variable

10.2 Architectures
-------------------

1. **Architecture client-serveur**
   - Clients demandent des services à des serveurs
   - Centralisé

2. **Architecture pair-à-pair (P2P)**
   - Chaque nœud est client et serveur
   - Décentralisé
   - Exemples : BitTorrent, Ethereum

3. **Architecture à trois niveaux**
   - Présentation, application, données
   - Utilisé pour les applications web

10.3 Services Distribués
-------------------------

**Services fondamentaux** :
- **Service de noms** : Mapping noms → adresses (DNS, LDAP)
- **Service de temps** : Synchronisation horloges (NTP)
- **Service de réplication** : Copie de données sur plusieurs nœuds
- **Service de consensus** : Accord sur une décision (Paxos, Raft)

10.4 Algorithmes de Consensus
------------------------------

**Problème du consensus** :
- Plusieurs processus doivent s'accorder sur une valeur

**Algorithme Paxos** :
- Algorithme de consensus tolérant aux fautes
- Phases : préparation, acceptation, apprentissage

**Algorithme Raft** :
- Algorithme de consensus plus simple que Paxos
- Leader election, log replication, safety

10.5 Tolérance aux Fautes
--------------------------

**Types de fautes** :
- Faute de crash (processus s'arrête)
- Faute omissive (processus ne répond pas)
- Faute byzantine (processus envoie des informations incorrectes)

**Modèle de tolérance aux fautes** :
- Modèle crash-stop
- Modèle byzantin

**Algorithmique** :
- Algorithmes tolérants aux fautes (FT)
- Systèmes distribués avec réplication

================================================================================
PARTIE 11 : SYSTEMES TEMPS REEL
================================================================================

11.1 Concepts Fondamentaux
---------------------------

**Système temps réel (RTOS)** :
- Système dont les réponses doivent être fournies dans des délais prédéfinis

**Types** :
- **Temps réel dur (Hard RT)** : Dépassement de délai = catastrophe
  - Exemples : contrôle aéronautique, médecine
- **Temps réel mou (Soft RT)** : Dépassement de délai acceptable
  - Exemples : multimédia, jeux

11.2 Caractéristiques
----------------------

- **Prévisibilité** : Temps d'exécution déterminable
- **Basse latence** : Réponse rapide
- **Scheduling préemptif** : Tâche à haute priorité peut préempter
- **Gestion de mémoire statique** : Pas d'allocation dynamique (évite la fragmentation)
- **Minimisation des interruptions** : Temps de traitement réduit

11.3 Algorithmes de Scheduling
-------------------------------

- **Rate Monotonic Scheduling (RMS)**
- **Earliest Deadline First (EDF)**
- **Least Laxity First (LLF)**
- **Fixed Priority Scheduling**

11.4 RTOS Populaires
---------------------

- FreeRTOS
- QNX
- VxWorks
- RT-Linux
- μC/OS
